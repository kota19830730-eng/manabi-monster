# v12.9.1 こうしんの 穴を 直す（2026-09-12・sw 136）

ユーザー「タブレットが 更新画面 でないけど どう なってますか？」

## 何が 起きて いたか

- GitHub Pages は **ぜんぶの ファイルを `Cache-Control: max-age=600`（10分）**で 送る。
- sw.js の install は `cache.addAll(FILES)` だった。これは **ブラウザの HTTP キャッシュを 通る**。
- 前の 版を 入れて から 10分 いないに つぎの 版が 出ると、新しい 版の 箱（`manabi-monster-v135` など）に **HTTP キャッシュに のこって いた 古い ファイルが 入る**。
- 結果：タブレットは「番号だけ 新しくて 中身は 古い」。SW は もう 最新と 思って いるので **お知らせも 出ない**。つぎの 版が 出る まで なおらない。
- この 日は 版を 数分おきに 出して いた（v12.4〜v12.9 ＝ sw 129〜135）ので はまりやすかった。

## 直し

`sw.js` の install を **`cache.addAll(FILES.map(u => new Request(u, { cache: 'reload' })))`** に（かならず サーバーから 取り直す）。
smoke が「install に cache: 'reload' が ある・ふつうの addAll(FILES) が ない」を 見る。

はまって いた タブレットも、この 版（136）を 取りに いく ときに 取り直すので **つぎの 起動で 自動で なおる**（セーブは 消えない）。

## たしかめ方（本物の Chrome）

scratchpad の `swt/run.js`（node の http サーバーで 古い 版を 配り、とちゅうで 新しい 版に すりかえる・CDP で 見る）。
- 直す 前：開き直すと キャッシュは v135 なのに 中身は v12.8 の まま。
- 直した あと：お知らせが 出て、開き直すと 新しい 中身（しるしの news v99.9）。
- 注意：headless Chrome の `--user-data-dir` を 長い パスに すると CacheStorage が「Unexpected internal error」で こわれる → **短い パス**（`C:/Users/win11/AppData/Local/Temp/mmud…`）で。

## もどさない

- install の `cache: 'reload'` を はずさない。
- ファイルを 足す ときも `FILES` に 足すだけで よい（取り直しは まとめて かかる）。
