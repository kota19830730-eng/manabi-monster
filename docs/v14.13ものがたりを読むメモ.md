2026-09-20・claude-5e。ユーザー「息子の 読解力が 低いので これを 高める 問題が あれば いい。壁打ちしましょう」。

## 2. ユーザーに 聞いた こと（AskUserQuestion）

- **つまずき**＝「長い 文を 読みたがらない」「読んでも 意味が 入って こない」
  （「なぜ？で 止まる」「気もちが 読めない」は **えらばれて いない**）
- **進め方**＝A（読解ステージ）＋ B（しゅぎょうばで 読み方）の セット
- **文章**＝物語文から。中身は「すこし こわい／ふしぎ・冒険／スポーツ・できなかった こと／いきもの」**ぜんぶ**

**ここが いちばん 大事**：えらばれた 2つは 読解の いちばん 手前の つまずき。
だから **「200字の 文章を 読んで 4問」は 出さない**（かたまりを 見た しゅんかんに 閉じる）。

## 3. 決めた かたち：「ものがたりバトル」

**文章を 一気に 見せない。ザコを 1体 たおすごとに 話が 1〜2文 進む。**

```
てき 1/13
┌────────────────┐
│ ものがたりを 読む            │
│ ┃ 十月の 金よう日。けんたは    │  ← 話は ここまで
│ ┃ ぞうきんを 持って、音楽室へ  │
│ ┃ 向かった。      [🔊きく]   │
│ けんたは どこへ 行きましたか。 │
└────────────────┘
 [音楽室] [図書室] [体いく館] [校てい]
```

| つまずき | どう 効くか |
|---|---|
| 長い 文を 読みたがらない | **字の かたまりを 一度も 見せない。** 1画面 1〜2文。気づいたら 514字 読み終わって いる |
| 読んでも 意味が 入って こない | **1〜2文ごとに「だれが・どこで・何を した」を たしかめる。** 意味を 作りながら しか 進めない |

### 少しずつ 長くする はしご
core の ザコの ならび（lv1 4体 → lv2 4体 → lv3 4体）に **そのまま 乗る**。

| | 1画面の 文章 | 聞く こと | 実測（1本め） |
|---|---|---|---|
| 場面 1〜4（lv1） | 1文 | だれが・どこで・何を した・どんな | 31〜37字 |
| 場面 5〜8（lv2） | 2文 | どう なった・なぜ・どんな 気もち | 31〜45字 |
| 場面 9〜12（lv3） | 2〜3文 | なぜ・どう かわった | 50〜63字 |
| ボス | **お話 ぜんぶ**（まきもので 読む） | なぜ・気もちの かわり方・推し量る | 514字 |

**1回 たたかうと お話 1本（514字）を 通して 読んで いる。でも 本人は そう 感じない。**

### たからばこ
ことばの 意味（語い）を 聞く。**その 文も いっしょに 見せる**。
たからばこは 3問めにも 出る ので、**まだ 読んで いない 場面の ことばを 聞かない ように**（実測で 見つけた）。

## 5. もどさない ところ

- **文章を 一気に 見せない。** 1画面 1〜2文から 始めて 少しずつ 長くする（ユーザーの 答え＝「長い 文を 読みたがらない」）。
- **`story: true` の ステージでは ふくしゅう・リベンジ・中ボス・まとめ問題を 出さない**（`ui/battle.js`）。
  話の とちゅうに よその 問題が 入ると 話が 切れる。中ボスは 同じ 場面を 2回 聞く ことに なる。
- **サポート（にがて教科）の `easy`（4/4/4 → 5/5/2）だけ 外す。**
  ヒント先出し・コンボガードは のこす（やさしさは 消さない）。easy を 通すと 話の 後半が 落ちる。
- **たからばこの 問題は その 文を いっしょに 出す**（まだ 読んで いない ことばを 聞かない）。
- **fitPrompt の はしごの 3つめ（`--storyk`）を 消さない。**
  話の 字も 縮まないと、タブレット（800×1280）で 問題文の 下が 切れる＝実測。
- **`refitSoon()` を 消さない。** 字の ファイルが あとから とどく・ヒントが 出ると カードの 高さが 変わる。
  そのあと 合わせ直さないと 切れる（`#dokkai:1` で 231/203 の はみ出しを 実測）。
- **まきものの 高さは `--stage-h`。`vh` に もどさない**（画面ぜんたいの 拡大縮小に 合わず 画面から はみ出た）。
- お話の 題名は **ひらがな**（金の 見出しは かん字が つぶれて 見える）。

## 10. B案：しゅぎょうばの 読み方の コツ

**`js/content/lessonkoku3.js`（新）**＝`MQ.lessons.add('kokugo3-6', {...})`。読みこみは lesson3.js の あと。

- **1本めの コツは「なぜ」の 解き方では ない。**「だれが・どこで・何を した の 3つだけ さがす」。
  ユーザーの 答え（長い 文を 読みたがらない／意味が 入って こない）に 合わせた もの。
  **「ぜんぶ おぼえなくて いい」と 先に 言う**のが いちばん 大事。
- せつめい 3画面 → いっしょに 2問 → ひとりで 3問（いつもの しゅぎょうばと 同じ）。
- **steps の `when` は ぜんぶ 同じ**（問題の unit が ぜんぶ「ものがたりを読む」だから）。
  出しわけは **`make` の 中で 問題文を 見て**（`kind(q)`＝why／kimochi／who／where／how／what）。
  `make` が null を かえすと つぎの step に 進む しくみを 使って いる。
- **しゅぎょうばの カードにも 話の 箱**（`js/ui/dojo.js` の `card()`）。
  これが ないと 話が 見えず 答えられない。
- **`dokkai3.make` は しゅぎょうばの ときは お話を えらび直さない**
  （`opts.lv && !('boss' in opts)` で 見わける）。
  えらび直すと `pickFrom` が 何回も よばれて **1回の しゅぎょうで お話が まざる**。

たしかめ方：`#dojo:koku`（通す）`#dojo:koku:ex`（せつめい）`#dojo:koku:step`（3たく）。
