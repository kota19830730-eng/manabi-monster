## 1. ラスボスの 頭が かくれる → 直した（公開ずみ）

### 何が おきて いたか（実測・800×1280＝タブレット・ステージ 700）

| もの | 場所（ステージ px） |
|---|---|
| アリーナ | y0..210 |
| `.bossinfo`（名前／弱点＋ため の 2行） | x280..390 **y6..52** |
| ラスボスの 絵（`.v3`） | x274..384 **y31..150** |
| エリアボスの 絵 | x264..382 **y24..149** |

**パネルの 2行め（弱点＋ため）が ちょうど かんむりの 上に のって いた。**
`.bossinfo` を うすく して 撮ったら、デビルカイザーの **金の かんむりと 白い つのが まるごと かくれて いた**
（`#last|css=.bossinfo{opacity:.25}` で 確認）。
sw 180 で ラスボス 6体を 96マスで 描き直して 背が 高く なった ぶん、v12.8 の「2行の パネル」に ぶつかった
（当時の コメント「3行に すると ラスボスの 頭に かぶる」＝2行でも かぶる ように なって いた）。

### 直し方

**ボスの 名前を 左上の HP バーの 中へ**（`.hpbar__name`）。この バーは そもそも ボスの HP なので、
名前と いっしょの ほうが 分かりやすい（ふつうの RPG と 同じ）。
右上の パネルは **弱点と ため の 1行だけ**に して `top: 6px → 4px`。

結果（ぜんぶ 800×1280 で 実測）：

| 画面 | パネル | 絵の 上 | かぶり |
|---|---|---|---|
| `#last`（デビルカイザー） | y4..23 | y30 | なし |
| `#boss`（イワサイドン） | y4..18 | y24 | なし |
| `#last1`（おばけキング） | y4..23 | y32 | なし |
| `#last6`（メイオウハデス） | y4..23 | y32 | なし |

**もどさない こと**
- `.bossinfo` を **2行に もどさない**（また かんむりが かくれる）。
- `.hpbar` の `position: relative` と `.hpbar__name` の `background: none` を 消さない
  （`.enemy__name` の こい わくが 出て HP バーを かくす）。
- ボスの 名前を さがす ときは **`.hpbar__name`**（前は `.bossinfo .enemy__name`）。
  harness と `tools/bossart/patch-harness.js` も 直して ある。

**この 直しは 別の セッションの commit `a73582b`（sw 183）に いっしょに 入って 公開ずみ。**
smoke ALL OK・`#flow` エラー 0・520×780 と 800×1280 で 目で 確認ずみ。

## 2. ボス戦が 重い ＝ 原因は 分かった。**安全な 直しは もう ない**

### はかり方（新しい 道具）

**`tools/fxcheck/bossab.js`**（新）＝ ボス戦の 画面が おちついた あとの 3秒を はかる。
CPU を 4ばい おそく して タブレットの まね（dpr 2・800×1280）。
**じゅんばんを かえながら 交互に まわして 中央の 値**（この PC は 1.6ばい ぶれる）。

```
node bossab.js last 3 base= noglow="|css=.arena .bx__glow{animation:none!important}"
SETTLE=14000 node bossab.js last 3 base=          # ラスボスは 出るまで 時間が かかる
```

「コマ」＝3秒の あいだに 画面を 描いた 回数。多いほど なめらか。

### 実測（CPU×4・3秒）

| 画面 | 3D の 面 | コマ | おそいコマ |
|---|---|---|---|
| ふつうの たたかい | 188 | **504** | 2 |
| ラスボス | **681** | **47〜74** | 31〜48 |

**ボス戦は ふつうの たたかいの 約10分の1**。これが「重い」の 正体。

### 犯人は「3D の 面（GPU の 層）の 数」。動きでも 大きさでも ない

くらべた もの（ぜんぶ 同じ 条件で 交互に）：

| ためした こと | 面 | コマ | わかった こと |
|---|---|---|---|
| そのまま | 681 | 47〜74 | — |
| **絵を 半分の 大きさに**（画素は 1/4） | 681 | 71 | **ほとんど 変わらない**＝画素の 数は 関係ない |
| 光る ところの 呼吸（`bxGlow` filter）を 止める | 681 | 58 | 変わらない |
| 3D の 動きを **ぜんぶ 止める** | 681 | 88 | **ほとんど 変わらない**＝動きは 関係ない |
| 動きを steps で へらす | 681 | 58〜61 | 変わらない |
| **よこ・上下の 面を ぜんぶ 消す** | 223 | **363〜462** | **面の 数だけが 効く** |

つまり **画面に 1コマ 出す たびに 681まいの 3D の 面を ならべ直す**のが 重さ。
何も 動いて いなくても、ほかの ものが 1つでも 動けば 全部 やり直す。

なめらかさの さかいめ（面の 数 → コマ）：
**188→504 ／ 323→363 ／ 433→132 ／ 503→133 ／ 681→47**。
**だいたい 350まい いかなら なめらか。**

### なぜ ラスボスだけ 重いか

| もの | 箱 | 面 |
|---|---|---|
| ふつうの てき（48マス） | 7 | **25** |
| 主人公（48マス） | 66 | 167 |
| エリアボス（64マス） | 27〜79 | 84〜250 |
| **ラスボス（96マス・sw 180）** | 83〜155 | **247〜514** |

デビルカイザー 1体で **514面＝ふつうの てきの 20ばい**。
sw 180 で「もっと カッコよく・マス数 増やしても いい」と 言われて 96マスに した ぶんが そのまま 層の 数に なった。

### 面を へらす 方法を 3つ ためした → **ぜんぶ 見た目が 変わる**

止めて 撮った 絵を 画素で くらべた（ボスの ところ 280×330・同じ 絵なら ちがう画素 0）。

| やり方 | 面 | ちがう画素 | 目に つく（30こえ） |
|---|---|---|---|
| ① 画面で 小さい 面を 作らない（22px² みまん） | 503 | 1484 | 596 |
| ① を ゆるく（4px² みまん） | 616 | 298 | 84 |
| ② 箱を 大きく まとめる（`tol` 2） | 425 | 12748 | 6622 |
| ③ となりに 9わり かくれた 面を 消す | 634 | 730 | 391 |

- ①②③とも **のこった 面は ぜんぶ 絵の ふち（シルエット）に ある**ので、消すと
  けんが 細く なる／マントが 平らに なる／ふちに すきまが 出る。
- ①を 見えない ところまで ゆるめる（2px² みまん）と、へるのは **7面だけ**で 意味が ない。

**→ 見た目を 1画素も 変えずに 面を へらす 道は ない。**

### のこって いる 道（ユーザーに 聞く こと）

| 案 | 面 | なめらかさ | 見た目 |
|---|---|---|---|
| A いまの まま | 681 | 重い | そのまま |
| B ラスボスの 3D を 少し あらく（`tol` 2） | 425 | 2.5ばい | 絵の 中身は 同じ。ふちの つみきが 1マス（約1px）ぶん 四角く なる |
| C もっと あらく（`tol` 4） | 327 | **7ばい**（ふつうの たたかいと 同じ） | ふちが 2マスぶん 四角く なる |
| D せっていの「りったい」を 切る | 0 | いちばん 軽い | 平らな 絵に なる（いまも できる） |

**B・C は 前の 面（絵そのもの）は 1画素も 変わらない。変わるのは 3D の あつみの ふちだけ。**
実寸（112px）で ならべると 見分けは つきにくいが、**決めるのは ユーザー**。

## 4. 教訓

- **時間（1コマ ms）では くらべられない**（この PC は 1.6ばい ぶれる）。
  「3秒で 何コマ 描けたか」を **交互に 何回も** まわして 中央の 値で 見る。
- 見た目を 変えて いないかは **止めて 撮って 画素で くらべる**
  （harness の ログの `textContent` を さしかえて `getAnimations()` を pause＋currentTime 固定に すると
  同じ 絵が 何回でも とれる＝ちがう画素 0 が 出る ことを 先に 確かめる）。
- **`#last` の ような 長い モードでは `|js=` の setTimeout は 動かない**（virtual-time が 進まない）。
  ログが 出た あとに 何か する なら `Object.defineProperty(log, 'textContent', ...)` で わりこむ。
- **ほかの セッションと 同じ ツリー**。この 作業中に 別の セッションが `git add -A` 系の commit を して、
  こちらの 直しかけ（battle.js・style.css・harness.html）が `a73582b`（sw 183）に いっしょに 入って 公開された。
  **直しかけを ツリーに 置いたまま 長く 調べものを しない**（先に commit するか、HEAD の 写しで 作業する）。
