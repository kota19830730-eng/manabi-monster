# v14.16 ラスボス戦で「書く 問題」の 反応が 悪い（2026-09-21）

ユーザー「息子の タブレットでは まだ ボス戦が 重く やりにくい みたいです。
**特に 書く問題が 反応悪くて ストレス**。他の バトルは 問題無し。」
→ そのあと「**重いのは ラスボスのみです**」。

sw 184（ラスボスの 絵を かるく）・sw 185 の あとの 話。**ラスボス だけ**が 対象。

---

## 1. 原因（ぜんぶ 実測）

### ラスボスだけ 3つ ちがう

| | ラスボス | ふつうの てき・エリアボス |
|---|---|---|
| 3D の 面 | **360まい** | 29〜44まい |
| 絵の 大きさ | **184×199px** | 98×107px |
| **光る ところの「呼吸」** | **29個** | **0個** |

光る ところの 数は 310体を 数えた（`scratchpad/glowcount.js` 方式）：
ハデス 54・ブリザードキング 39・ダークロード 25・デビルカイザー 23・おばけキング 17、
つぎが テンショウトリ 14・テンガイキリン 13。**310体 中 274体は 0〜8個**。

### なぜ「書く 問題」だけ ひどいか

書く 処理そのものは **5ms しか つかって いない**（EventDispatch の 合計）。
ゆびを 動かす たびに 画面を 1まい 出す 必要が あるのに、
**画面を 組み立てる 係（viz）が 74% ふさがって いて 13コマ/秒しか 出せない**。だから 線が 飛ぶ。
見て いるだけの 演出は カクついても「見た目」で すむが、書くのは 手が 止まる ので すぐ 分かる。

---

## 2. 直した こと

### ① 光る ところが 多すぎる 絵は「呼吸」させない（いつでも 効く）

`js/core/blocks.js` の `el()`：`.bx__glow` が **`GLOW_ANIM_MAX`（12）より 多い**絵は、
その 光 ぜんぶに `bx__glow--still` を つけて `animation: none`（`css/style.css`）。

- `bxGlow` は **`filter: brightness()` を 動かす** ので、動く たびに その 場所を 塗り直す。
- 止まるのは **ラスボス 5体＋テンショウトリ・テンガイキリンだけ**。310体 中 303体は いままで どおり。
- **光そのもの（box-shadow）は のこる**。呼吸が 止まるだけ。

### ② 書いて いる あいだ アリーナの 3D を その場で 止める

`js/ui/battle.js` の `makeMemo`：`beginAt` で `.battle` に `is-writing`、`endStroke` で **0.9秒後**に 外す
（かん字は 何画も つづけて 書く ため すぐには もどさない）。`clear()`（つぎの 問題）では すぐ 外す。
CSS は `animation-play-state: paused`（**`animation: none` に しない**＝止まるだけ なので 見た目が 飛ばない）。

### ③ 書いて いる あいだ、重い てきだけ 2D の 絵に 入れかえる ← **これが 本命**

`js/ui/battle.js` の `foeArt()`：3D の 面が **`FLAT_FACES`（200）より 多い**とき だけ、
`.enemy__img3d--heavy` の しるしを つけて **2D の 絵（`.enemy__flat`）を となりに 置く**（ふだんは `display: none`）。
`is-writing` の あいだ だけ 3D を 消して 2D を 出す。

- **ふつうの てきには つけない**（29〜44まい＝もともと 軽い）。切りかわりを 見せない。
- `whiteOut()` は `.enemy__img:not(.enemy__flat)` に した（かくれた 2D を つかまない＝いままでと 同じ 動き）。

## 3. 結果（CPU×4・タブレットの まね・3回を 交互に・中央の 値）

**1.5秒 ゆびを 動かして、線の 点が 何点 拾えたか**（＝線が どれだけ 飛ぶか）：

| | ひろえた 点 | 画面の コマ |
|---|---|---|
| ふつうの たたかい（合格ライン） | 29% | 208 |
| **ラスボス まえ** | **13%** | **35** |
| **ラスボス あと（①②③）** | **28%** | **138** |

**点の ひろえ 2.2ばい・コマ 3.9ばい ＝ ほぼ ふつうの たたかい並み。**

## 4. 測り方の 教訓（2回 まちがえた）

**`tools/fxcheck/spwarm.js`・`scratchpad/writeprobe.js`**（ゆびを CDP で 動かして 測る）。

1. **ボスの「ふつう／本気」パネル（v12.7）が 画面を ふさいで いた。**
   `elementFromPoint` が BODY を 返し、**指が メモに 届いて いない のに 測って いた**。
   → さわる 前に `.bosspick__btn--norm` を click する。
2. **`#last` は さいしょの 約18秒が 前座の ザコ**（24〜49面）。ラスボス（360面）は その あと。
   → **`#stage .foes .v3 .f` が 250まい いじょうに なるまで 待つ**（`MINFACE`）。
3. **1点ずつ 返事を 待つ 測り方は 本物の 指と ちがう**（ページの おそさが そのまま 待ち時間に 化ける）。
   → 返事を 待たずに 60回/秒 で ちょうど 3秒 動かし、**canvas が 何点 ひろえたか**を 見る。
4. この PC は 空いて いる ときは 問題が **再現しない**（同じ 条件で 1.4秒〜8.9秒）。
   くらべる ときは **かならず 交互に・中央の 値**。

**まちがえた 鑑定**：はじめ「ボスの 動きを 止めれば 直る」と 見立てたが、
正しい 測り方では **②だけでは ほとんど 効かない**（13% → ほぼ 変わらず）。
**層ごと 消す（③）が 効く**。①は 書きごこちには 効かないが、本体の 仕事を 3〜4割 減らす ので のこす。

## 5. もどさない こと

- `GLOW_ANIM_MAX` を 大きく しない（29個の filter アニメが また 走る）。
- ③は **重い てきだけ**（`FLAT_FACES` 200）。ぜんぶの てきに つけると ふつうの たたかいで
  いらない 切りかわりが 見える。
- `is-writing` は `animation-play-state: paused`（`animation: none` は 見た目が 飛ぶ）。
- `whiteOut()` の `:not(.enemy__flat)` を 消さない。
