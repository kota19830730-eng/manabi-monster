# v14.3 画面が 広がる わざの カクつき（2026-09-14・claude-06・未公開・作業ツリーに 未コミット）

ユーザー「画面が 大きくなる 必殺技が 多少 カクつく から なめらかに。クオリティは 下げないで 何とか ならないかな？」

## やった こと（見た目は 同じ）

8コンボ〜の わざで アリーナ（上の バトル画面）を 56% に 広げる 動き（0.28秒）を、
**高さ（height）の アニメ → GPU が 動かす translate／scale** に した（`js/ui/battle.js` の `grow()`・`css/specialfx.css`）。

- 高さは さいしょに 広げた あとの 大きさに して、
  ① アリーナを 上に ずらして おいて もどす（下の へりと かげが のびて いく ように 見える・上は 画面の 外）
  ② 上に くっついて いる もの（上の バー・ボスの パネル・コンボ・ためゲージ・カウンターの 帯・相棒の 帯）は 反対に ずらす
  ③ 空の グラデーション（空・ボスの 暗さ・わざの 暗い 空）は 下を 中心に のばす
  を 同じ 時間・同じ 速さで 動かす。下に くっついて いる もの（地面・主人公・てき・ふきだし・アイテムボタン）は ①と いっしょ。
- ゆれ（is-shake）・コンボの ポン と ぶつからない ように transform では なく **translate／scale（1つずつの プロパティ）**。
- `.arena.is-big` の 背景は transparent（空は .arena__sky が ぜんぶ おおう。ゆれで 画面の 上に はみ出した ぶんが 前と 同じ 見た目に なる）。
- translate が ない ブラウザ・動きを へらす せってい は 前と 同じ 高さの アニメ（`is-growcss`）。harness（virtual-time）は すぐ 広げる（いままで どおり）。
- たしかめ：harness **`#growshot:<わざ>:<ms>`**（ぜんぶの アニメを 同じ 時間で 止めて 撮る）で 前の 版と 画素で くらべた。
  動いて いる あいだは ふちの 1px みまんの ずれだけ・広がりきった あとは 同じ（bolt 8画素・star は はしの 1列だけ 35／255）。
  smoke ALL OK ×3・`#flow` エラー 0（HEAD＋こちらの 変更だけの ツリー C:/mqt143 で）。

## わかった こと（こちらが 本当の 原因）

**カクつきの 正体は 広がる 動きでは なく、わざの はじめの 0.3秒ほど 画面が 出ない こと。** 広がる 動きは ちょうど その あいだに おこるので、
つぎに 出た コマで もう 広がりきって いて「ぱっと 大きく なって カクつく」ように 見える（前の 版も この 版も 同じ）。

- 重いのは **カットインの 3D の 主人公（面 約300まい）**。かくすと わざの はじめ 0.7秒に 画面に 出る コマが 17 → 31・
  GPU の ラスター 320 → 146ms・Paint 197 → 19回（`tools/fxcheck/growcut.js`）。つぎが **技名の 光る 字**（SVG の ぼかし・かくすと 23コマ）。
  光の 粒（Canvas）・集中線は ほとんど かわらない。
- この PC（Chrome 50こ）では わざの はじめ 0.7秒は 15〜30コマ/秒。広がる 0.28秒の あいだに 画面に 出る コマは 前も あとも 3〜6（`growtrace.js`・CPU ×4）。
  → **広がる 動きを GPU に した だけでは この PC では 目に 見える ちがいは 小さい**（メインの 仕事と アリーナの 描き直しは なくなった）。

## ためして やめた こと

- **広がる 動きを「重い コマが 画面に 出てから」はじめる**：rAF の 間かくは GPU の おくれを 見せない（メインは 17ms ごとに 進む）。
  Element Timing（画面に 出た 時間）は 8回 中 0回しか 来なかった。決めうちの 時間は 端末で ちがい、ヒットの 重い コマと ぶつかる。→ やめた（すぐ はじめる）。
- **カットインを 先に 作って おく**（前の 問題の あいだに・opacity .002）：メインの 描き直しは 半分（40 → 19ms）に なったが、
  GPU の ラスターは へらなかった（240 → 233ms）。登場の アニメ（大きさが かわる）で 描き直す らしい。
- **カットインの 主人公を flat（上の 面なし）に**：ポーズで うで・頭を 手前に たおす ので 上の 面が 見える＝あなが あく。やめた。
- 画面の 録画（Page.startScreencast）は 30コマ/秒 ぐらいで、とれない コマと 止まった コマが 見わけられない（道具は けした）。

## のこり（ユーザーに 聞く）→ ユーザー「カットインを 軽く する 案を 作って 見くらべる」（2026-09-14 午後）

## カットインを 軽く する 案（2026-09-14 午後・作業ツリーに 未コミット）

### はかり直して わかった こと（上の「本当の 原因」を 直す）
- **主人公だけ かくしても 止まる 長さは ほぼ 同じ**だった（この PC は 1回ごとに ±50ms ぶれる）。前の「主人公を かくすと 17 → 31コマ」は ぶれの 中。
- 大きいのは **カットインまるごと**（かくすと GPU の ラスター 307 → 180ms・いちばん 長く 止まる 241 → 152ms）と **技名の 光る 字**（→ 216ms）。
  1つの 部品では なく **わざの 1コマめに ぜんぶ 描く** のが 重さの 正体。
- 主人公は **メインの Paint**（CPU ×4 で 238 → 63ms）＝**タブレットの CPU で 効く**。
- **カットインを 0.3秒 あとから 出す** と、わざの はじめの 止まりが カットインなしと 同じに なる（CPU ×4 で 174 → 76〜105ms）。
  カットインが 出る ときに 小さい ひっかかりが のこる → 主人公を 軽く する と へる。
